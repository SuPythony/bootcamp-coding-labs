Assignment 1: Marriage Pact — short answers
=============================================

Q1. reserve vs resize — and the capacity you chose in get_applicants.
    YOUR ANSWER:
    reserve allocates memory to the vector (changes it's capacity) but doesn't
    actually change it's size and does not defualt initialize. Resize changes
    the size and default initializes the new elements.
    students.txt had 1000 lines so I chose a value near but greater than that
    as the capacity, so that a few more records added does not cost reallocation.
    If I would have chosen the capacity to be less than 1000 then reallocation
    would have been required while adding elements, which would have been costly.


Q2. What does it mean for a std::ranges algorithm to take a projection?
    Give one example from your find_matches (or explain why a projection
    didn't help).
    YOUR ANSWER:
    Projection applies some function to the values before actually checking
    the predicate. The projected values are used in the predicate.
    In find_matches, I have used projection in std::ranges::copy_if as we
    had to compare the initials of each name to the initials of the given name,
    so I applied a projection to get the initials for comparison in the predicate.


Q3. Iterator invalidation in run_mixer. Which strategy did you choose
    (erase-returns-next-iterator / indices / restart) and why?
    What specifically goes wrong with the naive approach?
    YOUR ANSWER:
    I used erase-returns-next-iterator, as it will be the most efficient, due to
    not needing to loop over elements with no matches again before moving forward.
    In the naive approach when we erase the current name, all the iterators ahead of
    it are invalidated as the vector data positions change, and an old iterator might
    now point to different or invalid data.


Q4. at() vs []. When, if ever, would you reach for vec.at(i) over
    vec[i] in this assignment?
    YOUR ANSWER:
    at(i) will give an out_of_range error if i<0 or i>=vec.size(), [i] will not give such
    an error and result in undefined results. I'll use vec.at(i) when I'm not sure if i
    satisfies the bound for the vector and need to do error handling. But if I'm sure that
    i is within the bounds, I'll use vec[i] as it's faster and there's no risk of an error.
